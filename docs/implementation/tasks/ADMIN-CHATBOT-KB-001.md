# ADMIN-CHATBOT-KB-001 — Admin-managed chatbot knowledge base

Status: implemented and verified locally on 2026-11-07; owner local acceptance pending.
Release policy: local only. No push, merge, deployment, Production database access or feature flag change.

Migration `0025_managed_faq` extends `0024_recap_retention`. Three tables in `app_private` hold FAQ identity, append-only revisions, and a singleton publication generation. An identity has a stable UUID, optional unique built-in ID, current draft and public revision pointers, optimistic version, and timestamps. Same-FAQ foreign keys constrain both pointers. Revisions carry EN/DE questions, aliases, answers, evidence, and actor metadata. Runtime privileges and RLS protect all three tables; the app runtime cannot rewrite or delete a revision. There is no public mutation API.

The Admin Knowledge Base supports search, filters, history and reference inventory. Save creates a draft revision. Publish validates the current draft and makes it public; subsequent edits leave that public revision intact. Unpublish clears the pointer. Restore copies history into a fresh revision, either as a draft or, after confirmation, as the public revision. A row lock and optimistic version reject stale requests. The existing audit service commits with each successful mutation and records only the actor, action, FAQ ID, revision/version and timestamp.

The 17 packaged FAQs and canonical owner guide are unchanged. Public retrieval runs the existing selection and safety checks first. A stand-alone Managed FAQ matches a normalized explicit question or alias only when the existing retrieval has no source and returns insufficient knowledge. A linked FAQ may replace only the verified built-in it explicitly names when that built-in wins. Publication rejects ambiguous aliases or candidates that cannot win their intended queries. Unpublishing a replacement exposes the built-in again. Managed citations use `admin_managed` with a revision-specific ID and one public VGU reference, without official dates, line numbers or guide provenance.

Preview runs the same selection with a temporary draft overlay on published knowledge. It reports language, answer/fallback, selected source and classification, and conflict or selection outcome. It has bounded input and concurrency, creates no audit event or persistent data, and does not invoke AI. All Admin routes use existing active ADMIN authorization and private no-store responses; writes require CSRF. Publication requires complete bilingual text, a stable HTTPS VGU source and allowed evidence. Restricted, high-risk and time-sensitive content is excluded; validation screens for obvious personal data, secrets, unsafe markup and links. A reference does not prove the claim; the publishing Admin must check accuracy and suitability.

Each worker checks the PostgreSQL generation on demand every 15 seconds and loads a validated immutable snapshot only on change. Publication changes and generation increments are transactional. The public check is asynchronous and bounded to 350 ms or one quarter of the request budget, whichever is lower. A busy healthy instance typically sees changes within 15 seconds plus the next request; idle instances refresh when next queried. Refresh errors or invalid snapshots drop the managed layer and retain built-ins; database/validation failures retry after three seconds. A previously loaded snapshot can remain visible until its refresh window expires. No new infrastructure, dependencies, background task, AI or flags.

Focused evidence: 164 backend chatbot/source/migration/audit tests; one PostgreSQL 17 lifecycle test from migration 0024 to 0025; 96 frontend tests in five suites. The live test used real runtime privileges and two Admins, and checked CSRF, stale conflicts, draft isolation, publication, restore, audit, citations, collision, outage fallback and corrupt snapshots. Two independent caches and retrieval services refreshed within 16 seconds of publish at the default interval; subsequent transitions used an accelerated check interval. Local browser used the real API and disposable PostgreSQL; EN/DE, save, preview, publish, unpublish, restore, Escape/focus restoration, stale edit recovery and desktop/390px/320px widths were checked. Backend wheel, Ruff, focused mypy, frontend TypeScript, lint, format and production build passed; existing bundle advisory remains. Production and physical mobile hardware were not verified.
