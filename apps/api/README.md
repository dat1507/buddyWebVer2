# VGU Buddy API

FastAPI backend for the VGU Student Companion Platform.

## Local setup

```bash
python3.12 -m venv .venv
python -m pip install -r requirements-dev.lock
python -m pip install --no-deps -e .
```

On Windows, use `py -3.12 -m venv .venv` for the first command. `requirements.lock` contains the
runtime-only dependency set; `requirements-dev.lock` adds the checked development, build, and audit
tools. Both files are generated from `pyproject.toml` with Python 3.12 and pin transitive versions.

Activate the virtual environment, then run:

```bash
uvicorn app.main:app --reload
```

FastAPI exposes its interactive documentation at `/docs` and its OpenAPI schema at
`/openapi.json`.

## Credentialed CORS

The API accepts browser credentials only from the exact origins in `CORS_ALLOWED_ORIGINS`.
The value is a comma-separated list of HTTP/HTTPS origins without paths, queries, fragments,
credentials, or wildcards. When the variable is absent, local development permits only
`http://localhost:5173` and `http://127.0.0.1:5173`.

Production should set the first-party frontend origin explicitly. Credentialed requests permit
only `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, and `OPTIONS`, with `Accept`, `Content-Type`, and
`X-CSRF-Token` request headers. Unknown origins, methods, and headers fail CORS preflight checks.
Same-site production deployments should still keep the exact public frontend origin configured so
an accidental cross-origin topology change does not broaden access.

## Database configuration

Copy `.env.example` into your deployment secret manager or an ignored local `.env`. The application
does not auto-load `.env` files. Docker Compose reads it only when passed with `--env-file`; supply
the database URLs directly to the relevant Python process:

- `DATABASE_URL` is read only by FastAPI. Use the dedicated `vgu_buddy_runtime` login created by the
  first migration, set its strong password outside source control, and copy the appropriate
  direct/session/transaction connection string from Supabase Connect.
- `DATABASE_MIGRATION_URL` is read only by Alembic. Use the privileged direct connection; never use
  the transaction pooler for DDL or expose this value to the API process.

Remote URLs must use TLS. Port 6543 is treated as transaction pooling: SQLAlchemy's local pool and
prepared-statement caches are disabled. Direct/session connections use a bounded application pool.
Localhost may explicitly use `sslmode=disable` for the BE-005 development database only.

## Model foundation

All persisted application models inherit `app.models.Base`. The base pins their tables to the
non-exposed `app_private` schema, gives Alembic deterministic constraint names, and provides:

- `id`: native UUID primary key with application and PostgreSQL generation fallbacks.
- `created_at`: non-null timezone-aware creation timestamp generated by PostgreSQL.
- `updated_at`: non-null timezone-aware timestamp generated on insert and included automatically in
  SQLAlchemy updates when the caller does not supply a value.
- `deleted_at`: nullable timezone-aware soft-delete marker.

`deleted_at` does not install an implicit ORM query filter or define a retention policy. Services
must apply the appropriate active/deleted predicate explicitly, and direct SQL writers must maintain
`updated_at` themselves. Domain tables and their migrations remain owned by their corresponding
implementation tasks.

`app.models.UserRole` defines the only supported application roles: `USER` and `ADMIN`. It is a
string enum so future persistence and API schemas can share the exact uppercase contract. The enum
does not create a table, grant permissions, authenticate a request, or authorize an endpoint; those
responsibilities remain in later authentication tasks.

## Local PostgreSQL + pgvector

The repository-level `docker-compose.yml` runs PostgreSQL 17 with pgvector 0.8.6. It binds only to
the loopback interface, requires a non-empty local password, waits for PostgreSQL readiness, and
stores data in the named `postgres_data` volume.

From `apps/api`, copy the template and set a unique local-only `POSTGRES_PASSWORD`:

```bash
cp .env.example .env
```

Then, from the repository root, validate and start the database:

```bash
docker compose --env-file apps/api/.env config --quiet
docker compose --env-file apps/api/.env up -d --wait postgres
```

The image installs pgvector without mutating the database outside Alembic. Confirm that the
extension is available with:

```bash
docker compose --env-file apps/api/.env exec postgres \
  psql -U postgres -d vgu_buddy \
  -c "SELECT default_version FROM pg_available_extensions WHERE name = 'vector';"
```

Set `DATABASE_MIGRATION_URL` in the Alembic process to the local `postgres` URL, including
`sslmode=disable`, then apply the migrations:

```bash
python -m alembic -c pyproject.toml upgrade head
```

The baseline migration deliberately creates `vgu_buddy_runtime` without a source-controlled
password. Set one interactively so it does not enter shell history:

```bash
docker compose --env-file apps/api/.env exec postgres \
  psql -U postgres -d vgu_buddy -c "\password vgu_buddy_runtime"
```

Set `DATABASE_URL` in the FastAPI process to that local runtime-role URL, including
`sslmode=disable`. `GET /api/health/database` should then return `200 {"status":"ok"}` after a real
database round trip.

Stop the service while preserving local data with `docker compose --env-file apps/api/.env down`.
Adding `--volumes` permanently removes the local database volume and should be used only when a
clean reset is intended.

Run the schema boundary migration with:

```bash
python -m alembic -c pyproject.toml upgrade head
```

It creates the non-exposed `app_private` schema, the least-privilege runtime role, and default
revocations for `PUBLIC`, `anon`, `authenticated`, and `service_role`. Future table migrations must
keep tables in this schema, explicitly enable appropriate RLS as defense in depth, and test their
grants. Neither database value may use a `VITE_` prefix or appear in frontend code.

`GET /api/health/database` performs `SELECT 1`, returning `200 {"status":"ok"}` only after a real
round trip. Missing or unreachable configuration returns a sanitized 503 response.

The declarative base and domain tables remain assigned to BE-006 and later domain tasks. Supabase
Auth is not used; FastAPI remains the application authentication authority.
